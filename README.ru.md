# WakaTime для Orca

[English version](README.md)

Плагин для [Orca](https://github.com/stablyai/orca), который считает рабочее время в [WakaTime](https://wakatime.com) — так же, как это делают плагины для WebStorm, VS Code и Cursor.

## Что считается

| Что вы делаете в Orca | Что уходит в WakaTime |
| --- | --- |
| Открыт файл в редакторе | heartbeat по файлу: язык, проект и ветку определяет `wakatime-cli`, категория `coding` |
| Сохранили файл | heartbeat с `--write` и `--human-line-changes`: сколько строк вы изменили вручную |
| Открыт дифф | категория `code reviewing` |
| Работаете в терминале | `Orca Terminal` в проекте worktree; пока агент в нём работает — `ai coding` |
| Встроенный браузер | домен (без пути и параметров); `localhost` и `*.local` — `manual testing`, остальное — `browsing` |
| Нативная сессия агента | `Orca Agent`, категория `ai coding` |
| Время AI-агентов (Claude, Codex и др.) | `wakatime-cli` сам разбирает их логи; когда агент заканчивает работу, плагин запускает `--sync-ai-activity` |

Проект и ветка определяются по папке worktree, поэтому worktree Orca (`~/orca/workspaces/<repo>/<branch>`) попадают в тот же проект, что и основной репозиторий. Для worktree на SSH-хостах передаются имя репозитория и ветка.

### Когда идёт время

Как в IDE: только когда **окно Orca на переднем плане и вы что-то вводите** (клавиатура или мышь за последние 5 секунд). Правила WakaTime соблюдаются: новый heartbeat уходит при смене файла или вкладки, раз в 2 минуты на тот же объект и всегда при сохранении. Если Orca свёрнута или вы отошли, время не идёт; паузы склеивает сам WakaTime (по умолчанию в пределах 15 минут).

Фокус и простой определяются средствами ОС:
- **Windows** — фоновый `powershell.exe` с `GetForegroundWindow` / `GetLastInputInfo`;
- **macOS** — `ioreg` и `lsappinfo`;
- **Linux (X11)** — `xprintidle` и `xdotool`, если они установлены.

Если определить фокус не удаётся, плагин переходит в запасной режим и считает только действия во вкладках: переключения, правки, сохранения.

## Установка

1. Нужны `~/.wakatime.cfg` с ключом (`api_key = waka_…` в секции `[settings]`, ключ — на <https://wakatime.com/api-key>). Если раньше стоял WakaTime в другом редакторе, файл уже есть.
2. Orca → **Settings → Plugins**: включите систему плагинов.
3. Нажмите **Install plugin**, выберите **Git URL** и введите:
   ```
   https://github.com/nknwns/orca-wakatime#v0.1.1
   ```
4. Проверьте запрошенные возможности и включите **WakaTime**.

`wakatime-cli` берётся из `~/.wakatime/`. Если его нет или он устарел, плагин скачает свежий релиз с GitHub (проверка раз в сутки), как требует [гайд WakaTime](https://wakatime.com/help/creating-plugin). Бинарник общий с WakaTime-плагинами других редакторов.

Воркер плагина запускается вместе с первым событием Orca (агент сменил статус, создан worktree) или командой плагина, а дальше работает постоянно.

## Команды

Доступны в палитре Orca (`Ctrl+Shift+J` на Windows и Linux, `Cmd+J` на macOS; наберите «WakaTime»); горячие клавиши можно назначить в **Settings → Shortcuts**.

- **WakaTime: Status** — версия CLI, наличие ключа, работает ли определение фокуса, последний heartbeat.
- **WakaTime: Today's Time** — то же, что показывает строка статуса в IDE.
- **WakaTime: Open Dashboard** — открыть дашборд.
- **WakaTime: Pause Tracking / Resume Tracking** — пауза; состояние сохраняется между перезапусками.

Названия команд на английском: Orca не локализует манифесты плагинов. Уведомления показываются на языке интерфейса ОС (пока русский и английский).

## Настройки

Все стандартные настройки WakaTime из `~/.wakatime.cfg` (`exclude`, `include`, `hide_file_names`, `hide_branch_names`, `proxy`, `api_url` и т. д.) применяет сам `wakatime-cli`. Флаг `debug = true` дополнительно включает подробный лог плагина (Settings → Plugins → лог плагина).

## Как это работает и что важно знать до установки

Публичный API плагинов Orca (v1.4) не сообщает об открытых и сохранённых файлах. Чтобы знать, какой файл в фокусе, **плагин читает локальный RPC Orca** — тот же named pipe / unix socket, что использует `orca` CLI, с токеном из `orca-runtime.json`. Вызываются только два метода на чтение: `worktree.ps` (какой worktree в фокусе) и `session.tabs.listAll` (вкладки, их файлы и признак несохранённых изменений).

Что из этого следует:
- Это выходит за рамки возможностей, которые вы подтверждаете при установке. Воркеры плагинов — обычные процессы на вашем компьютере, поэтому технически это возможно, но знать об этом стоит.
- RPC внутренний и не стабильный: после крупного обновления Orca может понадобиться обновить плагин.
- Плагин запускает `wakatime-cli`, а на Windows — ещё скрытый процесс PowerShell для определения фокуса и простоя. Содержимое файлов читается только для подсчёта изменённых строк при сохранении (файлы до 2 МБ). Наружу уходит только то, что `wakatime-cli` отправляет в ваш аккаунт WakaTime (или на ваш `api_url`).

## Ограничения

- Номер строки и позиция курсора недоступны, поэтому `--lineno` и `--cursorpos` не передаются.
- Codex, запущенный из Orca, может хранить логи в каталоге Orca, а не в `~/.codex`. Такие сессии `wakatime-cli` не увидит.
- Проверено на Windows. Определение фокуса на macOS и Linux написано, но на реальных машинах ещё не проверялось — отчёты приветствуются.

## Разработка

```sh
npm test   # node --test, без зависимостей
```

Чтобы попробовать локальные изменения, добавьте папку репозитория в Orca: **Settings → Plugins → Development**.

Код:
- `src/activity.mjs` — чистая логика: что в фокусе и когда слать heartbeat;
- `src/tracker.mjs` — опрос и оркестрация;
- `src/focus-probe.mjs` — фокус окна и простой;
- `src/runtime-client.mjs` — RPC Orca;
- `src/wakatime-cli.mjs` и `src/zip.mjs` — установка и запуск CLI;
- `src/i18n.mjs` — тексты уведомлений.
